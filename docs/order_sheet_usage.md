# 人工操作单使用契约

`scripts/sandbox_order_sheet.py` 的终点是人工操作单文件。默认 dry-run 只打印预览；只有显式 `--confirm` 且全部校验通过才写文件。每次生成尝试仍追加 JSONL 审计，不连接券商、不发送交易指令。

选券保持原脚本的主板流动性池、未来 60 自然日解禁比例 ≥5% 剔除、三因子排名、KEEP_ZONE=10、TOP_K=5、slot 资金分配与整数手顺延计算。生成失败不会重新选股、缩量或填补虚构数据。原来的“每只卖一手示意”被真实账户股数取代；65bp 研究成本口径保留说明，现金检查按下面的交易费用计算。

## 真实输入准备

所有文件须放在 `reports/` 以外；本工具拒绝访问任何 `reports/` 路径、`.env`、`.mcp.json`，也检查符号链接的解析结果。不会导入原来的研究运行入口。没有账户或交易状态数据时，先停止，不要为跑通命令填写示例数值。

1. **面板**：`--panel` 指向真实的 `replay_data/live_panel.parquet`（默认路径）或维护者已有的等价面板。必需列：`date, symbol, isST, tradestatus, turn, amount, close, peTTM, pbMRQ, pctChg`。沿用 20 日波动率与 7 自然日面板新鲜度规则。面板日期不得来自未来，证券/日期不得重复。历史不足、无有效候选会拒绝。
2. **解禁数据**：`--events` 显式指向真实解禁 parquet 文件或分片目录，例如已有的 `replay_data/restricted_release`。接受原始列 `股票代码, 解禁时间, 占解禁前流通市值比例`，或规范化的 `sym, free_date, ratio`。比例使用原脚本的小数口径，0.05 表示 5%。不允许把缺失库或无效比例当作“无解禁”。本工具没有获取研究产物的默认路径。
3. **账户**：在换仓当天从券商 App 人工核实现金、总持仓、可卖数量和当日已成交金额，保存为下面的账户 JSON。导出不经过本工具，不需要提供账号、密码、API key。仅有股票名单的 registry 无法确定实际股数或资金，不可替代账户快照。
4. **交易状态**：从当时可核查的交易所/行情终端数据导出每只股票的停牌、ST 状态和状态数据时点；记录实际来源。腾讯免费报价没有可靠的显式停牌字段，本工具不会用“有价格/有成交量”猜测未停牌。没有真实状态导出就拒绝；禁止把下表的字段说明当成实际状态。
5. **报价**：可以使用有原始来源、证券级行情时点、上下限价及状态时点的真实行情 JSON；也可运行 `capture_order_quotes.py`，从腾讯实时端点获取原始价格、行情时间与上下限价，并合并第 4 步的真实状态。它保留原响应与 SHA-256，方便核查字段映射。请求失败、缺字段、过期或 ST 标记矛盾均拒绝，不返回替代价格。

账户 JSON 顶层字段契约（必填）：

| 字段 | 类型与含义 |
|---|---|
| `edge_id` | 字符串，必须与 `--edge` 一致；默认 `cold_lowvol_top5_hold` |
| `entry_date` | `YYYY-MM-DD`，冻结持仓的真实进入日期，不得晚于换仓日 |
| `as_of` | 含时区的 ISO 时间，真实核实账户的时间，必须为换仓日且不在未来 |
| `available_cash` | 非负数或十进制字符串，实际可用现金；不是总资产 |
| `daily_traded_amount` | 非负数或十进制字符串，换仓日截至 `as_of` 已成交的买入金额 + 卖出金额；实际没有成交才填 0 |
| `positions` | 持仓对象数组；真实空仓才填 `[]`。每项含 `symbol`、`shares`、`available_shares` |
| `positions[].symbol` | `sh.600000` 一类的完整证券代码 |
| `positions[].shares` | 真实总持仓股数，正整数；决定换出数量 |
| `positions[].available_shares` | 当日真实可卖股数，非负整数且不大于总股数，用于 T+1/冻结股数校验 |

状态 JSON（供采集报价使用）：顶层 `source` 是实际状态来源的可核查名称或地址，`statuses` 是按完整证券代码索引的对象。每项必须含 `observed_at`（含时区的实际状态时点）、`suspended`（布尔）、`is_st`（布尔）。状态覆盖所有潜在买卖证券；不确定的状态不能填 `false`。状态与行情均必须是当天、距校验时间 ≤300 秒。

报价 JSON：顶层 `source` 是实际行情来源，`quotes` 是按完整证券代码索引的对象。每项必需字段如下：

| 字段 | 类型与含义 |
|---|---|
| `price` | 有限正数或十进制字符串，真实最新价 |
| `observed_at` | 含时区 ISO 时间；行情源的实际报价时间，不得用 HTTP 接收时间替代 |
| `limit_up`, `limit_down` | 当日实际涨停价、跌停价，不得按固定 ±10% 猜测 |
| `suspended`, `is_st` | 明确布尔值；不接受缺失值或字符串 `"false"` |
| `status_source` | 可核查的真实交易状态来源 |
| `status_observed_at` | 含时区的实际状态时间 |

腾讯采集脚本使用原响应字段 3（价格）、30（行情时间）、47/48（涨/跌停价），检查代码、数值、时点和状态一致性；源格式改变会拒绝。没有每日限价的特殊证券不受支持，会拒绝。文件输入是一份可信人工导出契约；程序不会凭一个 `source` 字符串证明外部文件真实，维护者须保留实际导出来源，不能改写时间戳让旧数据通过。

## 命令

下面的路径仅表示维护者已经准备好的真实文件，不会创建或填充输入内容。采集脚本仅输出报价快照，显式运行才访问腾讯网络：

```powershell
.venv\Scripts\python.exe scripts\capture_order_quotes.py `
  --status-snapshot simulation_data\order_inputs\status.json `
  --output simulation_data\order_inputs\quotes.json
```

先默认预览；日期默认当前中国市场日期，也可显式传 `--rebalance-date YYYY-MM-DD`，但仍必须等于当日。行情文件与状态超过 5 分钟就必须重新获取，不能扩大新鲜度参数绕过：

```powershell
.venv\Scripts\python.exe scripts\sandbox_order_sheet.py `
  --panel replay_data\live_panel.parquet `
  --events replay_data\restricted_release `
  --account simulation_data\order_inputs\account.json `
  --quotes simulation_data\order_inputs\quotes.json
```

人工检查预览之后，在同样的命令后附加 `--confirm`，写出 `simulation_data/order_sheets/YYYY-MM-DD.md`。可用 `--output` 指定另外的安全文件路径。操作单、输入文件、解禁输入目录、审计日志及其锁不得重叠。

缺输入的安全演示：

```powershell
.venv\Scripts\python.exe scripts\sandbox_order_sheet.py --dry-run
```

没有实际账户/状态快照时会返回退出码 2，打印“缺少真实输入 --events, --account, --quotes；零模拟，拒绝生成”，不会去读取面板或写操作单；仍向默认 JSONL 记录拒绝结果。它是拒绝路径演示，不能冒充成功生成真单。

## 校验、幂等与审计

- 每笔股数必须为 100 的正整数倍；包括实际换出持仓，零股不能被静默取整。买卖股票不得重复，卖出数量不能超过当日可卖股数。
- 默认单笔上限 5,000 元、单日买卖合计上限 10,000 元，可通过 `--max-order-amount` / `--max-daily-amount` 调整。金额取生成价与实时价中较高者；单日上限还计入账户的 `daily_traded_amount`。
- 生成价相对实时价偏离严格大于 ±5% 就拦截；恰好 5% 通过该项。停牌、ST、触及涨跌停的两个方向均保守拒绝，缺失状态/限价也拒绝。工作日只允许 09:30–11:30、13:00–15:00 生成；午休、盘前盘后、周末拒绝。没有独立节假日日历，节假日还由真实当日报价/状态的新鲜度阻断。
- 佣金万3，默认最低 5 元（仅最低佣金可用 `--min-commission` 配置）；卖出印花税万5；双向过户费 0.00001。各项费用四舍五入到分。现金须覆盖全部买入本金/费用，以及极小卖出金额不足支付卖出费用时的差额；不预支尚未成交的卖出收入，也不拿另一笔待卖收入抵扣。
- 输入哈希覆盖面板、每片解禁文件、账户、行情的原始字节哈希，以及换仓日、资金、费率/限额参数。操作单正文使用固定的换仓/生成日期、输入时点与 hash；运行时钟只写入审计。同日同输入与参数在校验仍有效时，文件逐字节相同（UTF-8、LF），dry-run 和 confirm 的正文一致。
- 输出原子创建；已有相同字节复用，已有不同内容拒绝覆盖。同一个审计账本同一换仓日只能确认一个完整输入快照，后续不同快照即使更换输出文件也拒绝，防止分次生成绕过每日上限。这是保守的完整计划模式，不支持同日增量补单。应始终使用同一账本；更换/删除审计历史等同破坏人工审计边界。
- 默认审计日志 `simulation_data/order_sheets/audit.jsonl`；`--audit-log` 可在首次部署时指定持久路径。审计包含真实调用时间、换仓日、输入 hash、输出路径、模式、逐项校验、运行状态/错误。预览追加一条；确认先 `reserved` 持久化，再原子创建文件，随后追加 `written` 或 `unchanged`。日志读取、预留、写出及异常追加均受同一独占锁保护。
- 审计预留失败不写操作单。若文件已写但最终审计失败，程序返回 2 并明确提示“文件已写出/复用，完成审计失败，勿执行”，预留记录仍保留。异常退出可能留下 `.lock` 或仅有 `reserved`；后续保守阻断，不自动删除锁/释放预留。维护者先核对已有文件、真实成交和审计记录，再人工处理；不要直接重复执行纸面指令。

`--confirm` 只表示写文件授权，不表示成交或资金变化。每笔操作仍由人在券商 App 再次核对并手动执行；重复预览或重写相同文件从来不是新的交易指令。
