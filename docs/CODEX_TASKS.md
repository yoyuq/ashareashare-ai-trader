## 任务 1: 数据源能力盘点矩阵 (docs/data_source_inventory.md)

**目标**: 产出一张"本项目实际可获取哪些数据"的底牌清单, 供后续维护者决策用。
项目现有数据入口: akshare (已装, 注意其接口经常与底层 API 脱节)、东财 datacenter 直连 API
(已知可用的两个示例: `RPT_HOLDERNUM_DET` 股东户数, `RPT_PUBLIC_BS_APPOIN` 预约披露,
模式为 `https://datacenter-web.eastmoney.com/api/data/v1/get` + reportName/columns=ALL/
filter/pageSize=500 分页)、Baostock (日线/基本面)、腾讯实时行情。datapro MCP 不在范围。

**要求**:

1. 按类别枚举 akshare 与 A 股相关的公开接口 (行情/基本面/资金流/事件/舆情/宏观),
   加上你通过东财 datacenter 直连验证的新端点。
2. 矩阵每行字段:
   `接口/端点 | 数据内容 | 历史起点(实测) | 频率粒度 | PIT质量(是否带公告日/时点字段) | 覆盖度(抽样≥10只实测) | 调用稳定性(限速/超时/需代理) | 已知坑`
3. **历史起点与覆盖度必须实测**, 不许照抄文档声明。探测脚本化、可重跑。
4. 代理: 东财/akshare 部分接口需 `HTTP_PROXY=http://127.0.0.1:7897`; 失败时按
   `scripts/attention_collector.py` 内置的直连降级模式重试一次, 仍失败标记「不可用」。
5. 附带指出矩阵内**同义重复**的接口 (多个接口返回同一底层数据), 只保留最稳的一行。

**产出**: `docs/data_source_inventory.md` + `scripts/probe_source_inventory.py` (探测脚本)。
**验收**: 矩阵每行有实测证据 (脚本输出可对照); probe 可重跑; 测试/ruff 全绿。

## 任务 2: 真单操作单生成链路加固 (scripts/sandbox_order_sheet.py 及配套)

**背景**: 本项目的实盘执行方式是「程序生成操作单 → 人工在券商 App 手动执行」。
现有 `scripts/sandbox_order_sheet.py` 已跑通沙盘验证 (选券→叠层→整数手→操作单)。
目标: 把这条链路加固为防呆、幂等、可审计的可靠工具。

**需求清单**:

1. **防呆校验** (生成时逐条检查, 不通过则拒绝生成并说明原因):
   - 整数手 (100 股整数倍); 单笔金额与单日总金额上限 (可配置, 默认给保守值)
   - 生成价 vs 实时行情偏离 > ±5% → 拦截 (防止用了陈旧缓存价)
   - 标注停牌/ST/涨跌停不可执行状态; 资金充足性检查 (含费用: 佣金万3/印花税卖出万5/过户费0.00001)
2. **默认 dry-run**: 操作单默认只打印预览; 写出真单文件必须显式 `--confirm`。
3. **幂等**: 同一换仓日、同一输入快照 → 生成内容逐字节一致; 操作单带生成日期与输入快照哈希。
4. **审计日志**: 每次生成 append 到 jsonl (时间/输入快照哈希/输出路径/校验结果)。
5. **明确禁止**: 不接入任何券商 API、不做自动下单——链路终点是「人工确认的操作单文件」。

**测试**: 每条防呆规则至少 1 个单测 (mock 行情, 不联网); 幂等性 1 个单测。
**验收**: `pytest tests/ -m "not network"` 全绿; 手工 dry-run 演示输出。
